# BC 扩展商店

[English](README.md) | 中文

公开签名目录，可通过 BC 原生插件管理器验证并安装软件包。图形和标准工作流随核心一同提供；此目录增加可选能力。

公开目录从 `arzvaak/BharatCode-Extensions` 下载，无需登录 GitHub。可选的 `BC_EXTENSION_GITHUB_TOKEN` 凭据可提高 API 限额，并保存在原生凭据中。目录必须带有 Ed25519 签名和单调递增的版本号。软件包安装前必须精确匹配大小、哈希和当前平台证据；安装后保持禁用。

原生软件包会以宿主权限在整个 profile 中激活。只有显式在工作区启用并调用 `extension_load` 后，符合条件的 MCP 运行时才会附加到调用方 agent（智能体）和工作区。除持久内核以及已租用或正在工作的运行时外，闲置五分钟后会关闭未使用的运行时。不得声称进程隔离提供了沙箱。

种子条目仅提供发现信息，不代表资格已确认。在具体检查通过之前，依赖托管账户或特定应用的路线保持不可用。预览版不声明支持 macOS。

在此软件包中运行 `npm test` 和 `npm run build`。发布工作流会签名不可变目录并发布公开资源。不得默认将用户构建脚本视为已获批准。


## 预览构建与公开下载

尚未发布面向用户的安装器。当前工程分支可使用 Node 24 和固定版本的 pnpm 构建：在仓库根目录运行 `pnpm install --frozen-lockfile --ignore-scripts`、`pnpm run build` 和 `node scripts/extensions/core.mjs build`。运行 `node scripts/extensions/verify-core.mjs` 可使用独立的临时 profile。此冒烟检查结束后会删除其 fixture（测试前置数据）主目录，不会配置用户的实时 profile。

公开发行使用 `arzvaak/BharatCode-Extensions`，无需登录 GitHub。可选 GitHub 凭据可提高 API 限额。目录签名、软件包哈希、平台检查和资格证据仍决定是否可安装。核心扩展已内置；可选候选项将在工作流验证通过后开放。

卸载会移除管理器所拥有的软件包激活状态和安装记录，不会悄悄删除连接凭据或用户数据。断开连接需要显式操作。清除已下载归档会删除恢复缓存。更新需要为已安装版本声明受支持的迁移，且不得有正在运行的扩展工作。由于尚无经过资格确认、可逆的发布迁移，当前无法回滚。

## 版本与发布约定

应用版本、软件包 semver 和目录版本号彼此独立。符合资格的描述符必须包含精确的源提交、许可证、产物标识/大小/SHA-256、BC 版本范围和平台证据。每条 `qualificationEvidence` 记录都包含平台、打包安装/生命周期/工作流检查、源提交、归档 SHA-256、结果和 HTTPS 证据链接。每个声明的平台都必须为完全匹配的描述符源和产物通过全部三项检查；重复、陈旧或不完整的记录均不能授权安装。不兼容、受限或不符合资格的候选项仍会显示，但不能安装。目录版本号必须是递增的正整数；离线加载时会重新验证之前已验证过的目录。同一版本出现不同字节的软件包和目录版本替换都会被拒绝。

公开预览通过 `scripts/extensions/publish-public.mjs` 发布，使用外部 Ed25519 私钥和已审查的公开源提交。脚本先验证原生 Linux 打包安装清单和精确归档哈希，再上传十三个核心扩展包、签名目录和校验和。订阅适配器仍内置于应用中；其原生 OAuth 客户端配置尚待审查，因此不包含在公开快照中。公开仓库还提供六个初始技能。可选条目保留其资格状态；公开可下载不代表未经验证的工作流已可用。

此前的私有发布和晋级工作流属于独立的旧通道，不用于发布该公开通道；原有签名密钥也不是公开通道的密钥。操作系统应用签名使用单独的密钥，不能由目录签名替代。已发布产物的升级和恢复验收仍待完成。

请参见[验收台账](../../.workspace/core-extension-store/ledger.md)，查看 A1–E9 的任务、证据和待办事项。

## 本地依赖检查

候选项卡片提供 **Inspect local requirements**。此操作会通过 BC 原生子进程服务显式运行固定版本探测，复用 BC Node 运行时或本地已有的 Python/Jupyter/DuckDB/Typst/Tinymist/FFmpeg 安装及 LaTeX 引擎和构建工具。Technical Publishing 工作流包包含 BC LaTeX 初始技能，可通过 Skills Manager 检查并安装。它保留 LaTeX 模板，使用已有的 TeX Live 或 MiKTeX 安装；托管 TeX 发行版设置仍不可用。探测有五秒时限、受限输出、脱敏凭据，并会等待整个进程范围完成清理。探测不会在启动时运行，不会安装软件包、下载模型、启用工具或返回原始进程输出。检测到版本只代表检查结果；软件包、账户和工作流资格仍需单独确认。现有随附工作区依赖服务仍可单独使用。

## 托管运行时设置

只有当已签名目录包含适用于缺失依赖、当前 CPU 架构且通过当前平台资格检查的兼容运行时时，扩展卡片才会显示 **Set up managed requirements**。设置过程会验证已签名的发布清单、精确资源大小和 SHA-256，限制归档解压范围，检查所提供的版本，并以原子操作激活运行时。源目录将 x64 Typst 运行时标记为待资格检查，发布前不可用。原生资格检查会将按哈希固定的上游 Linux 和 Windows 可执行文件连同 Apache 许可证和第三方声明重新打包；各平台检查已签名软件包的安装、重新加载、PDF/SVG 输出、取消和移除。发布过程只接受该次运行的两份原生检查报告，据此生成已通过资格检查的描述符，并将精确归档纳入已签名发布清单。其他托管运行时仍不可用。**Managed runtimes** 会列出已安装版本并提供逐个移除操作；有 agent 工作正在运行或仍有依赖该运行时的扩展运行时处于活动状态时，将拒绝移除。
