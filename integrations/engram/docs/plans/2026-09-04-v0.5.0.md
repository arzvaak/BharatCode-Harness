# dsh-engram v0.5.0 Implementation Plan (Competitive Benchmarking: Project Identity + Ingest Closure + Injection Budget + Ranking Boost)

Design basis: a comparative report on the source code/docs of three memory-type competitors (hindsight coding-agents, OpenViking dsh-memory-plugin, dsh-mnemon). Conclusion: all three rely on an external server/daemon/cloud-side embedding; dsh-engram's "single-process, purely local, offline-capable" is the differentiating positioning — do not copy their architecture, only absorb four low-cost high-yield designs (the original report's P0 list). P1/P2 candidates are at the end of the document and are out of scope for this release.

Items confirmed as "no work needed": ① echo pollution protection — ingest already skips the plugin injection snapshot (`src/ingest/hook.ts`); ② durable attribution injection — the profile is already `createUserMessage` + `source: { kind: 'plugin', plugin, form: 'snapshot' }` (`src/index.ts`), will not be silently swallowed by a `complete: true` preset, no need to migrate the injection channel.

## Key Design Decisions (Locked In Before Implementation)

1. **Switch project identity to git origin** (learn from OpenViking workspace-peer): `projectKey` resolution order = git origin URL normalization → cwd hash fallback. Normalization rules: strip protocol and credentials, lowercase host, strip trailing `.git` and `/` (`git@github.com:a/b.git` ≡ `https://github.com/a/b`); in a worktree, `.git` is a file — follow the `gitdir:` pointer + `commondir` to find the real config then read origin — pure file reads, no subprocess. Database filename `project-<sha256(origin) first 24 hex>.db`. **Migration**: at startup, if the origin database does not exist but the old cwd database does → same-directory rename migration (zero data copy); if both exist → leave untouched and `console.warn` (do not merge, avoid silent conflicts). No new config items.
2. **Final-round ingest closure** (learn from OpenViking final commit, removes README Known Limitation #1): the `session/disposed` observer ingests the last round (slice = from the last `turn/start` to the end of the log, reusing the `ingestPreviousTurn` extraction pipeline). **Idempotency**: op_log records the ingested `(sessionId, turn)` key, dedupe check before ingest, the normal path and the disposed path do not duplicate. **Fallback**: disposed is a fire-and-forget observer, process exit may interrupt it — 5-second `AbortSignal.timeout`, failed/incomplete pending keys remain in op_log, replayed and made up on the next session's first pre-step. Failures still only warn, do not affect the conversation.
3. **Injection token budget + degradation line** (learn from OpenViking recallTokenBudget): add `injectTokenBudget` (default 1024, clamped 128–8192). Token estimate `ceil(len/4)`. Fill order by importance descending; if a whole line exceeds the budget, skip that line and try shorter ones (do not truncate content); after the budget is exhausted, collapse the remaining entries into one index line (`- [kind] #id first 40 chars…`) + a trailing `+N more; use engram_search`. `profileTopN` is kept as a count limit, first pick candidates then fill by budget, both take effect simultaneously.
4. **Multiplicative boost on search ranking** (learn from hindsight TEMPR tail): multiply two factors on top of the RRF fusion score — recency `1 + w_r * max(0, 1 - daysSince(lastAccessedAt) / decayAfterDays)`, proof `1 + w_p * log2(1 + accessCount)`. Coefficients go into Config: `rankRecencyWeight` (default 0.2), `rankProofWeight` (default 0.1), clamped 0–2, 0 disables. Pure ranking-layer change, the `last_accessed_at`/`access_count` fields already exist, **SCHEMA_VERSION unchanged (still 2)**.

## Task Breakdown

- **T1 project identity**: `src/project/identity.ts` (origin read/normalization/sha256 hash + worktree pointer resolution + cwd fallback); index.ts database rename + old database rename migration + dual-existence warn. Tests: identity.spec (normalization equivalence classes, worktree pointer, no-.git fallback), migration tests (construct an old database file, assert the rename/warn branches).
- **T2 final-round ingest**: hook.ts slice support "last round to end of log"; op_log idempotency key `(sessionId, turn)` dedupe check; `session/disposed` hook (5s timeout) + pending replay on the next session's pre-step. Tests: fake LLM fixtures, covering idempotency no-duplicate, disposed timeout landing in pending, replay make-up.
- **T3 injection budget**: config.ts add `injectTokenBudget`; renderProfile change to budgeted fill + degradation index line. Tests: budget truncation, skipping over-long lines, degradation line format, mixed CJK/Latin estimation.
- **T4 ranking boost**: search ranking layer multiplicative boost + two config coefficients. Tests: recency/proof each change the order, coefficients of 0 degenerate to the status quo.
- **T5 finishing**: README/README.en update (remove Known Limitation #1, add descriptions of the three new config items), design.md sync, composition test extension, v0.5.0 commit.

## Verified API Facts

- `session/disposed(session)`: scoped emit observer, fire-and-forget, the host does not wait for the callback (`packages/core/session/src/index.ts:62`; template usage `packages/session/session-title/src/index.ts:372`) — hence T2 must have the pending replay fallback.
- Current state of profile injection: `createUserMessage({ content, source: { kind: 'plugin', plugin: name, form: 'snapshot', sections } })` (`src/index.ts:89-92`).
- Current database naming: `project-${Buffer.from(process.cwd()).toString('hex').slice(0, 24)}.db` (`src/index.ts:107`).
- Current state of the ingest slice: between the last two `turn/start`s (`src/ingest/hook.ts`); final-round slice = from the last `turn/start` to the end of `events`.
- op_log already has an `audit(action, id, detail)` channel; the idempotency key and pending marker land directly in op_log, no new table.

## Follow-up Version Candidates (Not Done in This Release)

- Near-duplicate automatic merge: the cosine ≥0.97 tier automatically goes through supersedes merge (hindsight reconcile), routed separately from the 0.88 contradiction tier.
- Ingest activity signal admission: structural signals (char count/tool count/diversity) below threshold do not call the auxiliary LLM (mnemon background review admission).
- Git branch dimension visibility: nodes add a `branches` column, injection/search filter by the current branch (mnemon exclusive, needs schema v3).
- Distillation evidence chain: distill output records the list of merged ids as traceable evidence (hindsight observations).
- Hot/cold capacity tiering: byte-budget-driven archiving/backfill (mnemon); vector ANN index (sqlite-vec, reassess once scale comes up).
