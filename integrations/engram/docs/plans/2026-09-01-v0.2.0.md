# dsh-engram v0.2.0 Implementation Plan (Phase 2: Auto-ingest + Flywheel + Audit)

Design basis: the auto-ingest, contradiction detection, knowledge flywheel, and audit/privacy sections of `docs/design.md`. Phase 1 (v0.0.1) has been delivered: dual-database storage, hybrid search, 5 tools, and profile injection.

## Key Design Decisions (Locked In Before Implementation)

1. **Ingest trigger point**: Reuse the already-verified `agent/pre-step` waterfall — `step === 1` marks the start of a new round, meaning the previous round is complete. Read `agent.session.events` (the log; honor model-visible ⟺ logged) to extract candidate facts from the previous round. Async fire-and-forget, does not block the request; on failure, count it and do not retry.
2. **LLM routing**: Parse from the most recent `request/header` in the session log's `data.header.config.{provider,model}` (routing also comes from the log); Config may override as an optional `provider`+`model` pair. The LLM goes through `ctx.llm.stream` + `BlockAssembler` (the session-title-llm template), with `purpose: 'engram-ingest'` / `'engram-distill'`.
3. **Ingest tiers**: `ingest: 'off' | 'light' | 'eager'`, default `off` (opt-in, not in the release default). light = extract only from user messages, max 2 per round, confidence 0.3; eager = extract from both user and assistant messages, max 5, confidence 0.4.
4. **Contradiction detection**: On write, vector neighbors (cosine ≥ 0.88, same scope, active) → create a `contradicts` edge (from=new to=old) → report the candidate in the tool result, decided by the model/user (update or forget), does not block the write.
5. **Hit reinforcement**: Search hits get confidence +0.05 on touch (capped at 1).
6. **Distillation**: `engram_distill` is triggered explicitly. Take active entries sorted by importance, the top 30 → LLM outputs a JSON array of patterns (kind=skill|fact, supersedes ids) → write the new entry (vector = average of the merged ones), mark the old entry archived + supersedes edge, confidence inherits the mean.
7. **Decay**: At startup + every 24h on a timer (`ctx.effect` interval): active and importance < `decayImportanceBelow` (default 0.3) and lastAccessedAt older than `decayAfterDays` (default 30) → archived.
8. **Schema v2**: Add `source_round INTEGER`, `source_seq INTEGER` to the nodes table (attribution of the ingest source); `SCHEMA_VERSION = 2`, old databases are refused load (pre-release stance).
9. **Audit tools**: `engram_review(id)` (entry + source chain + supersedes neighbors + the last 20 operation-log entries for that id), `engram_stats()` (kind/status distribution, edge count, signal-to-noise ratio), `engram_export(format)` (writes a file to `dbDir/exports/`, returns path + summary, does not stuff the whole DB into context), `engram_distill(scope)`.

## Task Breakdown

- **T1 store layer**: schema v2, WriteInput/MemoryRecord extensions, `touchConfidence`, `review(id)`, `stats()`, `exportAll()`, `decay(options)`, `findContradictions(embedding)` + `linkEdge()`, `supersedeMany()` (for distillation). Tests: extend store.spec.
- **T2 ingest**: `src/llm/client.ts` (stream wrapper + JSON parse tolerance), `src/ingest/hook.ts` (previous-round event extraction prompt + tier logic + candidate writes). Tests: fake LLM fixtures.
- **T3 contradiction detection**: Wire into the store.write path (when a vector is present), return the candidate report.
- **T4 distillation**: `src/flywheel/distill.ts` (clustering extraction + supersedeMany) + decay. Tests: fake LLM.
- **T5 wiring**: 4 new tools, Config extensions (ingest/provider/model/decay/distillMaxInput), add `llm` to the entry inject, hook ingest into pre-step, decay timer. Tests: extend tools.spec.
- **T6 finishing**: composition test (9 tools + llm stub), README, v0.2.0 commit.

## Verified API Facts

- `ctx.llm.stream({ provider, model, messages, system, maxTokens, sessionId, purpose, signal })` + `BlockAssembler` (the `packages/session/session-title-llm/src/index.ts` template).
- Session event shapes: `request/header` → `data.header.config.{provider,model}`; `user/message` → `data`; `turn/start` → `data.turn` (the `packages/client/ui-usage-billing/tests` and `time-context` templates).
- `agent.session.events` is directly readable (the time-context template); `agent.session.id` is a SessionId (`String()` normalized).
- Pre-step waterfall: `next()` must be called, with reject branching (already implemented in phase 1).
