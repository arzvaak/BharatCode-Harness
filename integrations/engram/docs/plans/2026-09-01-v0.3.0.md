# dsh-engram v0.3.0 Implementation Plan (Phase 3: Web Admin Panel)

Design basis: the phase 3 section of `docs/design.md` + the confirmed decision (**host static page mode**: the host webServer serves the `/engram` admin page and the `/api/engram/*` data endpoints, not going through the host client module table — same as Lingshu /roleplay, and the billing host routing template).

## Architecture

- **API** (host half, all with loopback guards: peer socket + Host header + Origin/Content-Type checks for write operations, the billing `guardLoopback` pattern):
  - `GET /engram` → admin page (single-file HTML, inline CSS/JS, Simplified Chinese UI)
  - `GET /api/engram/stats` → merged stats of the two databases
  - `GET /api/engram/list?scope&status&kind&q&limit&offset` → paginated list (non-empty `q` goes through hybrid search; otherwise paginate by the filter conditions, including archived/forgotten — the admin view must be able to see all statuses)
  - `GET /api/engram/review?id&scope` → audit view
  - `POST /api/engram/update` (id/scope/content/kind?/importance?) → supersedes replacement-chain correction
  - `POST /api/engram/forget`, `POST /api/engram/restore`
  - `GET /api/engram/export?format=markdown|json&scope` → full-database export file stream download
- **store extensions**: `list(filter)` interface method (dynamic WHERE: scope/status/kind/substring + limit/offset + total count).
- **Page** (native HTML/CSS/JS): stats card row, filter bar (scope/status/kind/search box), memory list (content, kind/status badges, importance/confidence bars, source summary, time), row actions (detail modal = review, edit = update semantics into the replacement chain, forget/restore), export buttons (markdown/json), manual refresh.
- **Composition test**: add the real `@deepseek-ai/dsh-host-webserver` webserver, HTTP assertions for each endpoint + loopback-guard 403.

## Tasks

- **T1** store.list + tests.
- **T2** `src/routes.ts`: guards + API endpoints + page HTML (`src/page.ts`); index.ts wiring (webServer route registration, webServer is an optional dependency — a profile without webServer does not register the page).
- **T3** composition test (real webserver + HTTP assertions) + README + v0.3.0 commit.
