# Agent Note: 工作流导航与可关闭上下文面板

Status: implemented

[English](2026-10-08-workflow-navigation-and-context-disclosure.md) | 中文

## 问题

输入区的上下文面板混合了工作流导航和证据查看，没有明确关闭操作，还把依赖错误作为产品文案显示。用户需要切换工作区视图，同时保持运行任务和未发送消息。

## 决策

侧栏负责 Chat、Coding、Research 和 Writing 视图选择。展开导航显示简短说明；折叠导航保留可访问的工作流按钮。根级展示存储按会话保留选择。会话框架通过槽钩子读取同一可观察源，确保单一存储作用域，并在切换视图时保留原生会话工厂。

Using context 使用门户显示限制在视口内的面板，包含证据和显式刷新操作。明确的关闭按钮、Escape 和外部指针点击均可关闭它。关闭按钮和 Escape 将焦点还给触发按钮。查看失败时保留已有证据，并提供易懂错误和 Retry 操作。

原创内容过渡在快速切换时取消，并遵循减少动态效果设置。侧栏和对话框使用共享 BharatCode 时长变量。选择仅属于展示状态，不提交提示、不改变权限或执行目录。

## 考虑过的替代方案

**把工作流操作放在上下文面板内。** 这会混合导航与模型可见证据的引入，并把主要操作藏在输入区旁。

**每次切换工作流都重新挂载会话。** 这会丢失输入区 DOM，并可能丢弃未发送草稿。共享框架保留会话工厂。

## 后果

导航和上下文查看拥有独立、易发现的位置。测试验证视图切换时输入区身份与草稿保持不变、过时动画取消、折叠导航的可访问标签、门户位置，以及三种关闭途径。当前所选视图仍共享原生聊天内容；该变更不表示编辑器、阅读器或手稿布局已经完成。
