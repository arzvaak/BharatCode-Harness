# Agent Note：等待 PowerShell 启动提示符送达

Status: implemented

[English](2026-10-10-pwsh-startup-prompt-delivery.md) | 中文

## 问题

Linux 发布单元测试偶尔在 shell 重置后的首条 PowerShell 命令中返回被截断的提示符文本。就绪时间线显示，启动在收到唯一确认后结算，而受控提示符仍未送达。迟到的提示符在提交下一条命令后到达，错误地在命令输出到达前结算了发送。

## 决策

PowerShell 启动在返回会话前，要求每个会话独有的确认及捕获视口末尾已送达的受控提示符。仍要求现有后端 stdin 就绪证据与绝对启动期限。后续空发送等待提示符送达；既不重新提交设置，也不更改计时边界。

## 影响

消费方只会在启动提示符送达后获得会话。Bash 启动和交互命令就绪约定保持不变。持久化格式和公开接口没有变化。

## 验证

确定性的后端回归用例先在一次 stdin 就绪结算中送达确认，再在下一次送达提示符。修改前该用例失败，因为启动在第一次结算后就返回。现有真实 PowerShell Loader 组合检查同时验证重置、工作目录、环境、大量输出和命令就绪。

## 已考虑的替代方案

延长测试超时或重试整个测试套件会保留产品中的过早结算问题。固定延迟依赖主机速度，而非观察到的提示符送达。
