# 原生研究知识工作区

## 目的与已批准方向

Research 通过关联的笔记、来源、引用和发现支持对主题的持续研究。同一项目中仍可使用计算 notebook。用户批准包含关联 Markdown 笔记、来源引用和 Obsidian 兼容性的原生工作区。本文规定该实现。用户随后要求应用内阅读和导出到 Obsidian，并明确要求实施。

成功意味着用户可以收集来源、编写和关联笔记、重访证据、在 Obsidian 中编辑同一批文件，并运行 notebook，而无需切换项目或丢失草稿。聊天仍是入口。打开 Research 不会执行工作、向模型披露整个文件夹或改变会话身份。

## 已有接口边界

- `packages/client/ui-workspace/src/client/workflows/ResearchWorkspace.tsx` 已将来源、笔记、证据、文稿、工作区和运行分开。笔记当前使用通用文档面板。
- `packages/workspace/workspace/src/project-knowledge.ts` 和 `types.ts` 保存不可变工件修订及显式关系，包括锚定于精确引用片段和修订 ID 的引用。
- `packages/api/workspace-controller/src/knowledge.ts` 提供生成的知识 Remote 服务，并负责 notebook 准入和执行任务。
- `packages/api/workspace-controller/src/source-capture.ts` 和 `workspace-tools.ts` 保存研究来源并提供 agent 工具。
- `workspaceFiles.readEditable/saveEditable` 提供版本检查文件编辑。文档草稿与已有编辑器生命周期提供私有恢复。

复用这些契约，不引入并行证据存储、notebook runner、编辑器保存机制或模型权限系统。

## 范围

提供主题主页、Markdown 笔记库、笔记创建/编辑、内部链接导航与插入、反向链接、有界搜索、来源保存、引用插入和查看、已有证据视图以及计算 notebook 入口。包含使用同一 Host 服务的 agent 笔记接口。

Obsidian 兼容性指普通文件、支持的链接导航和外部编辑处理，不保证 Obsidian 插件、主题、数据库、Canvas 或完整块引用渲染。图谱视图、语义 embedding、云同步、自动文献监测和新的二进制文档 OCR 不在本次实现中。已有文档阅读器继续可用。

应用内阅读采用已有安全 Markdown 阅读器，支持表格、脚注、代码、数学和图片。不需要新图形引擎。导出生成可下载 ZIP，包含普通 Markdown 及引用的本地附件/notebook 构成的知识库文件夹，以及所引用已保存证据的可移植副本。导出报告缺失资源和字节限制。它绝不覆盖已有知识库，也不包含凭据、应用私有存储或 `.obsidian/`。

## 文件与身份

已注册工作区目录是知识库根目录。新项目可用 `Research.md` 作为可编辑主题主页，并建议采用 `notes/`、`sources/` 和 `attachments/` 目录。仅通过明确的初始化或创建操作建立它们。已有文件夹保留原结构。

Markdown 文件是权威作者内容。不得要求专有 front matter，也不得在发现期间改写文件。保留不支持的语法、front matter、Unicode、换行和用户格式。应用不得修改 `.obsidian/`。Git 元数据、应用私有状态、依赖目录和逃逸项目根目录的符号链接不参与笔记发现。

笔记索引包含项目相对路径、显示标题、别名、标签、标题层级、来源链接、文件版本与已解析外链。它是可重建的投影；删除索引不得丢失作者知识。已有工件修订 ID 仍是已保存证据的身份。不得混淆可变笔记路径与不可变修订身份。

## Host 服务与索引

在工作区包中增加专门的 research-library 模块，通过知识控制器提供公共类型和 Host API。职责如下：

1. 发现选定已注册项目根目录下的 Markdown 文档。
2. 尽可能采用已有 Markdown 解析工具解析支持的元数据和链接；链接提取排除代码围栏和行内代码。
3. 生成笔记列表、搜索结果、外链、反向链接和问题。
4. 独占创建笔记，不覆盖已有路径。
5. 通过已有版本检查文件 API 读取和保存笔记，再通过项目知识服务将保存修订捕获为笔记。
6. 通过已有不可变关系 API 插入和查看引用。

拟议的 Remote 操作为 `researchList`、`researchInspect`、`researchCreate`、`researchRefresh` 和 `researchCite`。编辑继续使用已有文件服务。每项操作验证已注册项目所有权及规范根目录范围。客户端绝对路径不能选择无关文件。请求与响应采用生成的 Remote 类型。

发现过程有界，报告部分结果，不得静默宣称完成：默认最多 10,000 个 Markdown 文件，每个索引文档 2 MiB，索引文本总量 64 MiB，每页返回 200 行。按项目相对路径确定性排序，并通过游标续页。超过限制的内容仍可由普通文件工具打开；明确说明未索引原因。

在打开知识库、应用成功保存、明确刷新和已有文件变更通知可用时刷新。合并事件；项目变化时使过时异步响应失效。外部变化后重载干净编辑器，对未保存编辑器显示冲突。搜索和反向链接必须标识部分/过时索引。不得静默覆盖外部编辑。

## Markdown 与 Obsidian 链接语义

支持标准相对 Markdown 链接和 Obsidian wikilink：`[[Note]]`、`[[folder/Note]]`、`[[Note|label]]`、`[[Note#Heading]]`。通过已有资源阅读器将文件嵌入作为安全附件链接/预览。按字面保留块引用等不支持形式，明确导航不支持，而不编造目标。

相对 Markdown 路径基于所在笔记解析。知识库根路径 wikilink 基于已注册根目录解析。仅文件名 wikilink 只在唯一匹配时解析；重复名称需选择目标。精确文件名优先于别名；歧义别名保留歧义。解码 Markdown URL 转义时不得将外部 URL 当作本地文件。拒绝路径遍历和逃逸根目录的符号链接。明确显示缺失笔记；创建需要用户操作及已验证路径。

反向链接标识引用文件及有界摘录。来源引用和语义关系不同于普通导航链接。不得推断每个链接都表示“支持”。

自动重命名传播延期：此版本不提供批量重命名操作。外部重命名会刷新索引并显示失效引用。已有通用文件操作不得声称会修复笔记链接。

## 来源与引用

来源获取与不可变保存继续使用已有来源流程。来源显示标题、原始 URL/路径、保存修订和可用状态。二进制来源如实显示提取可用性；不宣称不支持的 PDF 页码映射或 OCR。

对于已保存文本，用户选择片段并插入 Markdown 脚注，包含可读来源标题、可移植 URL 或相对文件链接，以及可用的引用或定位信息。分配无冲突脚注标签，将引用定义保留在 Markdown 文件中。未知页码不得添加。

通过比较后保存笔记，捕获其新不可变修订，并以 `cites` 及精确片段偏移/引用，将该修订关联到选定来源修订。串行执行此流程，并报告各持久步骤。文件保存后若关系保存失败，保留已保存笔记，显示“引用证据不完整”，并允许幂等重试。不得将部分保存描述为完成，也不得回滚用户无关的外部编辑。

引用查看器打开精确已保存来源片段，并区分当前、过时、缺失和仅保存副本的来源。外部 Markdown 引用无需私有元数据仍可阅读；导入脚注不自动宣称具有已验证的不可变片段证据。

## 用户体验

保留以聊天为入口的空状态和明确文档披露。研究主题主页提供 Markdown 概览、待解问题、笔记/来源数量及入口操作。问题是作者文本，不是新的强制数据库 schema。

打开的知识工作区包含紧凑笔记导航器、中央编辑器或阅读器以及外链、反向链接和引用上下文面板。复用共享主题 token、草稿恢复、保存/冲突指示和面板布局。保留 Files 空间及每会话工作流状态。窄容器采用面板堆叠，并提供键盘可访问控件及命名区域。

创建笔记、关联已有笔记、跟随链接、查看来源、插入引用、搜索和返回上个笔记都是明确操作。空、加载、断开、部分索引、冲突和写入失败状态互不混淆。点击笔记不得执行代码或提交聊天消息。

notebook 继续通过已有分析面板与任务控制器，以“Computational research”入口访问。保留输入捕获、kernel 信息、运行/取消/状态、错误及输出。笔记可链接 `.ipynb` 文件或已保存结果；打开该链接不会运行它。

## AI 集成

通过已有工作区工具注册提供有界列表/搜索、链接/反向链接查看、笔记创建和引用操作。使用与 UI 相同的 Host 实现。工具回执报告保存路径/版本、捕获修订、未解析链接、省略项和部分引用保存。

浏览/索引不代表加入模型上下文。保留明确选定上下文及已有交接契约。来源和笔记是证据，绝不是指令。在作者提案中区分来源引用、用户观察和 AI 推断。AI 对已有笔记的修改使用当前审核/diff 路径及基础版本检查；发现过程从不授权静默批量改写。

## 验证与验收

- Host 测试覆盖独占创建、根目录范围、逃逸符号链接、分页/限制、外部修改、过时响应和版本冲突。
- 解析器测试覆盖 Unicode/空格、Markdown 链接、别名、标题、歧义文件名、缺失笔记、嵌入、代码围栏和 URL 转义。
- 引用测试覆盖脚注冲突、精确修订片段验证、过时来源、部分保存/证据失败及重试幂等性。
- UI 测试覆盖创建/编辑/保存/重开、草稿恢复、链接导航、反向链接、引用、索引警告、键盘操作及项目切换。
- 浏览器审核在桌面及窄屏运行完整主题研究流程，包括外部文件编辑和未保存笔记冲突。
- 兼容性 fixture 使用含普通 Markdown、wikilink、附件、front matter 和 `.obsidian/` 的知识库；证明发现不改写任何文件，结果笔记无需应用私有存储仍可阅读。
- 已有 notebook 执行/取消与研究/工作区测试继续通过。配置的 kernel 可用时验证真实 notebook 执行；kernel 不可用与 UI 证据分开报告。
- 运行相关包检查、生成传输/类型检查和相关回归测试。在实现记录中登记精确命令/结果。

验收：收集两个来源，创建三个关联笔记，添加片段引用，跟随链接和反向链接，搜索，重启后重开，外部编辑笔记，无损处理同时编辑，并在同一项目到达可跟踪 notebook 运行。来源、草稿、无关文件和聊天状态保持完整。

## 实现与发布边界

规格批准后编写按依赖排序的实施计划：知识库/解析器契约、Host API、引用流程、UI、agent 工具和完整流程验证。使用已有原生传输与编辑器约定。

按用户全局规则，发布准备、打包、资格验证、发布和安装委托给使用 `max` reasoning 的 `gpt-6-luna`。主 agent 负责实现，并交接具体修改和验证证据。本规格不授权公开发布。
