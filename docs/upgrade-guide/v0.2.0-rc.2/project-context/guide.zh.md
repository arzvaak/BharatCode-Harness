# 项目证据和工作流交接

[English](guide.md) | 中文

## 变更

Workspace仍是稳定的项目标识。Workspace API组合现在挂载核心Project Knowledge服务和生成的`knowledge` API。注册选定的UTF-8文档、检索有界摘录、捕获不可变修订，并显式关联证据、相互冲突的决策或实施产物。文件只读，不会被改写；索引、捕获文本、关系和准备好的交接保存在私有`project_knowledge`存储域中。

“Send to session…”打开共享交接编辑器。选择现有或新目标会话，填写目标、选定证据、约束和未解决问题。准备阶段冻结证据，并在接收前显示过大源文件的省略信息。排队等待目标会话的下一轮；转向是单独的显式操作。输入框旁的“Using context”仅显示已接收提示关联的证据，包括源修订和缺失或过期状态。刷新会打开新的准备步骤，不会替换先前任务的证据。

工作流分配和交接接收是新增的仅日志会话事件。准确的模型可见交接文本使用现有带标识用户消息和持久化收件箱。关闭应用会保留排队输入；重试已提交交接会通过支持的代理运行时唤醒现有待处理消息。用户取消仍清空待处理输入。核心项目操作不依赖可选集成。

## 迁移

1. 保留现有Harness主目录、项目注册表、会话代次、凭据和模型路由。不移动源文件或配置目录。
2. 一起升级生成的主机和客户端API。历史日志无需改写。新增事件使用现有会话格式代次；兼容性确认记录位于`docs/persistence-changes/2026-10-08-bharatcode-context.md`。
3. 组合Workspace API的主机需要现有Session Controller和会话查询服务来启用交接操作。项目存储独立于可选记忆或搜索包。
4. 重启后用原标识重试排队交接。不要为了恢复而创建第二个任务。其他代理运行时应实现可选`resumePendingInput`能力，以唤醒保留输入而不生成另一条提示。
5. 本阶段注册提取后的UTF-8文本，而不是二进制或PDF原文件。文档阅读器和文本提取随工作流工作区交付。即使源文件消失，已有捕获证据仍可读取。

显式会话捕获复用现有的有界会话引用投影，保存捕获序号、格式代际以及省略的消息和字节数。刷新生成新修订；源会话缺失时仍保留已捕获证据。
